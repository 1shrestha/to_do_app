# To-Do List App

A working To-Do List app: a **React** front end plus a **REST API** that implements the endpoints planned in Assignment 7.
The API runs as Vercel serverless functions in production and inside the Vite dev server locally, so there is nothing extra to start.

## Run it locally

```bash
npm install
npm run dev      # app + API at http://localhost:5173
npm test         # 7 API tests
```

## Deploy to Vercel

1. Push this folder to a GitHub repository.
2. On vercel.com choose **Add New > Project**, import the repository and click **Deploy**. Vercel detects Vite and the `api/` folder on its own; no settings to change.
3. Copy the `https://your-project.vercel.app` URL. That is the Deployed Project URL for the submission form.

Or with the CLI: `npm i -g vercel`, then run `vercel --prod` in this folder.

## Features

Add a task (title, priority, due date, notes), tick it done, edit it, delete it, clear all completed tasks, filter (All / Active / Completed), search, sort, overdue highlighting.

## API (base path `/api/v1`)

| Action | Method | Endpoint | Success |
|---|---|---|---|
| Add task | POST | `/tasks` | 201 |
| List tasks (filter, search, sort, paginate) | GET | `/tasks` | 200 |
| Get one task | GET | `/tasks/:id` | 200 |
| Replace a task | PUT | `/tasks/:id` | 200 |
| Update part of a task | PATCH | `/tasks/:id` | 200 |
| Delete one task | DELETE | `/tasks/:id` | 200 |
| Delete all completed | DELETE | `/tasks?completed=true` | 200 |

Query parameters for `GET /tasks`: `completed=true|false`, `priority=low|medium|high`, `search=text`, `sort=title|dueDate|priority|createdAt|updatedAt` (prefix `-` for descending), `page`, `limit` (max 100).

Errors use one shape: `{ "success": false, "error": { "code": "...", "message": "..." } }` with status 400 (bad request), 404 (not found), 405 (wrong method), 422 (invalid value) or 500.

Task ids are UUIDs generated by the server (`randomUUID`), never by the client.

## How it works

- `api/v1/tasks/index.js` and `api/v1/tasks/[id].js` are the Vercel functions. Both re-export handlers from `lib/tasks.js`.
- `lib/tasks.js` holds validation and all CRUD logic. `lib/store.js` is the data store.
- `src/` is the React app. It talks to the API through `src/api.js`.

## Important: data storage

Tasks are kept in server memory (`lib/store.js`). That is fine for this assignment, but on Vercel the memory is cleared whenever a function instance restarts, and different instances do not share it, so tasks can disappear. For permanent storage, swap `lib/store.js` for a database such as MongoDB Atlas or Vercel Postgres; the handlers do not need to change much.
